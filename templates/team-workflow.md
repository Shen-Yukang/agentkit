# 和 AI 协作的约定

<!-- 由 agentkit 生成：升级时会被覆盖。项目自己的规矩写在 AGENTS.md 的 agentkit 段落之外，冲突时以项目规矩为准。 -->

这份约定对所有 agent 都一样：Claude Code、Codex、Kimi、Grok、DeepSeek，或者别的。下面的命令都写成 `python3 .agentkit/agentkit.py …`，任何能运行命令的 agent 都能用。

## 任务卡是唯一的记忆

聊天记录会丢，换个会话、换个 agent、换个人就没了。所以需求、人拍板过的事、做到哪一步，都记在任务卡里（`agentkit.toml` 的 `tasks.dir`，默认 `docs/tasks/<任务号>.md`）。

- 开工先运行 `task show`，读完整张卡再动手。
- 收工前更新「拆分」的状态和「交接」，再运行 `task handoff --agent <你是哪个 agent>`。
- 任务卡和代码一起提交。

## 工作节奏

1. **先复述**：用自己的话把需求写进任务卡（满足谁 / 解决什么 / 怎么算做完），列出要人拍板的事和拆分建议，然后停下（`prompt restate`）。
2. **等人确认**：「确认」只能由人在自己的终端运行 `task confirm` 填写。需求确认前，除了任务卡不改别的文件。确认之后又改了需求，确认会失效，要人重新确认。
3. **先重现**：修 bug 或改业务行为前，先写一个会失败的测试，运行并贴出输出，再问能不能开始改（`prompt repro`）。
4. **一次一步**：一次只做「拆分」里的一块。做完就停下，汇报做了什么、证据是什么，更新这一块的状态。
5. **证据用工具跑出来**：用 `checks` 的真实输出当证据，不要手写或编造结果（`prompt verify`）。
6. **3 轮上限**：同一个问题改了 3 轮还不对，停下来说明卡在哪里，建议换个思路或拆小，不要继续硬改。
7. **收工前交接**（`prompt handoff`）。

## 什么要问人

- 下面这些不要自己决定，写进任务卡「要人拍板的事」并附上建议：改共享模块还是局部改、对外接口和报错方式、用户能看到的文案、数据库结构、权限。
- 人在对话里拍板了，就把决定、谁定的、日期记进任务卡，下一个接手的人或 agent 才看得到。
- 需求里缺了三问中的任何一项，直接指出来，问清楚再继续。

## 边界

- 只改需求范围内的代码。顺手发现的其他问题，列出来，不要顺手改。
- 受保护路径不能改。被拦住时停下来说明为什么需要改，请人决定，不要想办法绕过。
- 不要提交、推送或调整远端权限，除非人明确说可以。
- 不要跳过 git 钩子（`--no-verify`），不要替人运行 `task confirm`。

## 提交之前

- 新开一个会话审一遍：Claude Code 用 `/selfcheck`；也可以运行 `review`，让配置好的几个审查者各开一个新会话来审。
- 用 `prompt pr-desc` 生成 PR 描述，第一行写任务号。

## 命令对照

| 步骤 | Claude Code | 其他能运行命令的 agent |
|---|---|---|
| 读任务卡 | 开会话时自动显示 | `task show` |
| 复述需求 | `/restate` | `prompt restate "<需求>"` |
| 写失败测试 | `/repro` | `prompt repro` |
| 跑检查拿证据 | `/verify` | `checks` |
| 自审 | `/selfcheck`（新会话） | `review` |
| 写 PR 描述 | `/pr-desc` | `prompt pr-desc` |
| 交接 | `/handoff` | `prompt handoff`，然后 `task handoff` |

不能访问仓库的聊天机器人：由人运行 `prompt start` 或其他步骤，把输出整段贴给它，再把回答整理进任务卡。
