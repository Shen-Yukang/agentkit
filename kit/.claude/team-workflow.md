# 和 AI 协作的约定

这份文件由 CLAUDE.md 引用，Claude Code 每次打开这个仓库都会读到。

## 工作节奏

1. **先复述**：需求不够清楚，或者改动会超过一个文件，先用自己的话复述需求，列出需要人拍板的事，等确认后再动手（`/restate`）。
2. **先重现**：修 bug 前，先写一个会失败的测试把问题重现出来，运行并贴出输出，再问能不能开始改（`/repro`）。
3. **一次一步**：每一步做完就停下，汇报做了什么、证据是什么，再进入下一步。
4. **每一步都要证据**：测试输出、截图、实际运行的命令和结果。没验证过的就明说“未验证”，不要编。
5. **3 轮上限**：同一个问题改了 3 轮还不对，停下来说明卡在哪里，建议换个思路，不要继续硬改。

## 边界

- 只改需求范围内的代码。顺手发现的其他问题，列出来，不要顺手改。
- 下面这些不要自己决定，列出来问：改共享模块还是局部改、对外接口和报错方式、用户能看到的文案、数据库结构。
- 不要提交或推送，除非人明确说可以。

## 提交之前

- 新开一个对话，运行 `/selfcheck` 审一遍这次的改动。
- 用 `/pr-desc <任务号>` 生成 PR 描述。
